ПРОВЕРКА РЕЦЕПТОВ НА ОЧКОВЫЕ ЛИНЗЫ И АВТОВОЗВРАТ КЛИЕНТОВ: N8N, POSTGRESQL, OLLAMA QWEN2.5-VL И TELEGRAM (DOCKER COMPOSE, CLOUDFLARE TUNNEL)
Эпизод 54. Канал: @ByteAutomate_AI

ЧТО ЭТО
Мастер фотографирует бумажный бланк рецепта в закрытый Telegram-бот салона. Локальная мультимодальная модель Ollama (qwen2.5-vl) считывает диоптрии и межзрачковое расстояние, n8n сверяет цифры с историей клиента в PostgreSQL и блокирует заказ при смене знака цилиндра или резком скачке диоптрий. Врач подтверждает рецепт кнопкой. Через 11 месяцев бот напоминает клиенту о проверке зрения. Без абонентской платы за сервис: платите за сервер.

В АРХИВЕ
- docker-compose.yml: PostgreSQL 16, Ollama, n8n, cloudflared (Cloudflare Tunnel); тома pg_data, n8n_data, ollama_data;
- .env.example: пример настроек (пароль базы, ключ шифрования n8n, домен, токен туннеля, чат врача, список врачей, чаты мастеров, модель Ollama);
- init.sql: таблицы clients (карта клиента, согласие на напоминание, дата визита) и rx_checks (проверенные бланки, решения врача, ограничения шага 0,25 дптр и диапазонов);
- optical_rx_n8n.json: сценарий n8n (30 узлов; идентификаторы подключений пустые): приём фото, чтение моделью, привязка таблицы и проверка значений, сравнение с историей, запись, карточка врачу с кнопками, удаление фото из чата, решение врача, ежедневный автовозврат;
- backup.sh: резервная копия базы рецептов (дамп PostgreSQL и архив настроек);
- Инструкция.txt: этот файл.

ВАЖНО ДО ЗАПУСКА (честные ограничения)
1. Автор стек, сценарий и SQL-схему на живом сервере не запускал и точность распознавания qwen2.5-vl на реальных бланках не проверял. Логика узлов Code проверена в Node на подставных данных; SQL на PostgreSQL не запускался. Теги образов (latest), узлы Telegram, Postgres, удаление сообщений, HTTP-запросов и имена параметров сверьте в своих версиях. После первого успешного запуска закрепите версии образов.
2. Данные. Локально остаются распознавание (Ollama), сценарий (n8n) и база (PostgreSQL): рецепты не уходят во внешние нейросети. Но фото бланка проходит через серверы Telegram, а трафик через Cloudflare Tunnel. Поэтому обезличивайте бланк ДО отправки в бота: закройте ФИО, телефон и дату рождения, клиент это только номер карты. Бот удаляет фото из чата мастера после обработки (проверьте работу удаления в своей версии Bot API).
3. Рецепты и медицинские данные: персональные данные особой категории (152-ФЗ), согласие клиента, хранение и передача, согласие на напоминания через Telegram. Проверьте у юриста; набор не даёт юридических гарантий.
4. Система не ставит диагноз и не заменяет врача. Она находит расхождения (знак цилиндра, скачок диоптрий, сдвиг оси) и блокирует заказ до решения врача. Заказ на завод набор сам не отправляет. Пороги (sph 1,00, cyl 0,75, ось 20 градусов) условные: подберите их вместе с врачом.
5. Точность распознавания зависит от бланка, света и почерка. Если таблица не опознана по подписям OD, OS, SPH, CYL, AXIS или значение не кратно 0,25, сценарий ничего не записывает и просит ручной ввод. Шаг 0,25 дптр проверьте по справочнику оптометрии.
6. Автовозврат. Бот не может написать клиенту первым: клиент должен сам запустить бота и дать согласие (поле consent_recall). Срок 11 месяцев задан в запросе узла «Клиенты к напоминанию».
7. Цифры 40 000 ₽, 90 000 ₽ и 11 месяцев в ролике иллюстративные параметры кейса и оценки владельца, не замеры.
8. Для мультимодальной модели нужны ОЗУ и желательно видеокарта; на CPU распознавание одного бланка может занимать десятки секунд (не замерялось). Подберите модель под железо.
9. Туннель открывает доставку сообщений Telegram на ваш n8n: редактор n8n закройте через Cloudflare Access. Условия бесплатного Cloudflare Tunnel проверяйте на сайте Cloudflare.
10. Резервная копия базы рецептов обязательна (см. чек-лист ниже).

ШАГ 1. СЕРВЕР
Нужен VPS с Linux, Docker и Docker Compose. Аренда: Timeweb Cloud по партнёрской ссылке https://timeweb.cloud/r/nf413716
ПОМЕТКА О ВОЗНАГРАЖДЕНИИ: ссылка партнёрская, автор канала получает вознаграждение, цена для вас от этого не растёт. Тарифы (по данным автора на момент записи от ~490 ₽ в месяц, не проверено) и бонус проверяйте на сайте.

ШАГ 2. ТУННЕЛЬ И БОТ
Создайте туннель в Cloudflare Zero Trust, маршрут вашего домена на http://n8n:5678, токен впишите в TUNNEL_TOKEN. В Telegram создайте бота у @BotFather (токен вносится в учётные данные Telegram в n8n). Узнайте chat_id чата врача (ADMIN_CHAT_ID), Telegram id врачей (RX_DOCTOR_IDS) и chat_id мастеров (RX_CHAT_IDS).

ШАГ 3. НАСТРОЙКИ
Скопируйте файлы на сервер, например в /opt/optical-rx. В папке:
  cp .env.example .env
  openssl rand -hex 32     (выполните дважды: POSTGRES_PASSWORD, N8N_ENCRYPTION_KEY)
Впишите значения и домен HOST. N8N_ENCRYPTION_KEY задайте один раз и никогда не меняйте.

ШАГ 4. ЗАПУСК
  docker compose up -d
  docker compose ps
  docker compose exec ollama ollama pull <модель из OLLAMA_VL_MODEL>
Должны работать postgres, ollama, n8n и cloudflared. Если контейнер не стартует, смотрите docker compose logs. Откройте редактор n8n и создайте администратора.

ШАГ 5. КАРТЫ КЛИЕНТОВ
Примеры в init.sql (карта 1001) удалите и заведите свои карты. Для автовозврата клиент должен дать согласие и запустить бота; тогда:
  docker compose exec postgres psql -U $POSTGRES_USER -d $POSTGRES_DB -c "UPDATE clients SET client_chat_id = 123456789, consent_recall = true WHERE card_no = '1234';"

ШАГ 6. СЦЕНАРИЙ
В n8n: Workflows, Import from file, optical_rx_n8n.json. Создайте учётные данные Telegram (токен бота) и PostgreSQL (хост postgres, база и пользователь из .env) и выберите их в узлах. Активируйте сценарий.

ШАГ 7. ПРОВЕРКА
Проверьте на своих бланках: чистый бланк с картой 1001 (должно быть «сходится с историей» или «блок», если значения расходятся), бланк со сменой знака цилиндра (блок), перекошенное или нечитаемое фото (ручной ввод), фото из чужого чата (бот игнорирует), нажатие кнопки не врачом (игнорируется), повторное нажатие (ничего не меняется). Сверьте точность распознавания с бумажными бланками на 20-30 примерах до реальной работы.
